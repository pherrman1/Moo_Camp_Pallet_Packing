\begin{abstract}
This document states only the \texttt{ReducedExactCoordinateMILP} constructed
by \texttt{gurobi\_coordinate\_solver.py}.  This is the model selected by
\texttt{configs/gurobi\_coordinate\_default.json}.  Each physical box has one
integer local coordinate and one orientation, while pallet assignment remains
binary.  Pairwise direction variables prevent boxes assigned to the same
pallet from overlapping.  Optional support constraints use exact horizontal
intersection areas.  The implemented objective minimizes the number of used
pallets.  All sets, parameters, variables, auxiliary linearizations, and their
sources in the input or configuration are described below.
\end{abstract}

\section{Modeling idea}

Every candidate pallet has the same dimensions and coordinate system.  A box
is assigned to exactly one pallet, so it needs only one local position and one
orientation.  It does not need a separate copy of its coordinates for every
candidate pallet.  Geometry is therefore indexed by boxes and box pairs;
pallet indices occur only in assignment, pallet activation, capacity, and the
constraints that activate non-overlap for boxes sharing a pallet.

The word \emph{exact} refers to this reduction: replacing pallet-indexed copies
of identical local geometry by one state per box does not approximate the
integer-grid packing problem.  Exactness remains relative to the configured
grid, allowed orientations, maximum candidate-pallet count, and active
constraints.  Section~\ref{sec:symmetry} records an important caveat concerning
two optional pallet-label restrictions enabled together in the supplied
configuration.

\section{Input data and preprocessing}

\subsection{Sources}

The model is built from two sources:
\begin{enumerate}[leftmargin=*]
 \item An MCPP/PL-100 JSON instance supplies the pallet and an \texttt{items}
 or \texttt{boxes} array.
 \item A JSON configuration supplies grid resolution, candidate-pallet and
 item limits, rotation and support modes, symmetry options, Gurobi parameters,
 and the type of area auxiliaries.  The supplied default configuration selects
 \texttt{model\_variant = reduced\_exact} and
 \texttt{area\_auxiliary\_type = integer}.
\end{enumerate}

The parser accepts several dimension-field schemas.  After normalization, let
$(L^{\rm mm},W^{\rm mm},H^{\rm mm})$ denote the physical pallet dimensions and
$(\ell_i^{\rm mm},w_i^{\rm mm},h_i^{\rm mm})$ the physical dimensions of box
$i$.

\subsection{Grid conversion}

Let $g\in\Z_{>0}$ be the grid size in millimetres.  It is read from
\texttt{grid\_mm}; if this value is the string \texttt{input}, it is read from
\texttt{meta.grid\_mm} in the instance, with 50 mm as the parser fallback.
Pallet dimensions are rounded down:
\begin{equation}
 (L,W,H):=\left(
 \left\lfloor\frac{L^{\rm mm}}g\right\rfloor,
 \left\lfloor\frac{W^{\rm mm}}g\right\rfloor,
 \left\lfloor\frac{H^{\rm mm}}g\right\rfloor\right).
 \label{eq:pallet-grid}
\end{equation}
The unrotated dimensions of box $i$ are rounded upward:
\begin{equation}
 (\ell_i,w_i,h_i):=\left(
 \max\left\{1,\left\lceil\frac{\ell_i^{\rm mm}}g\right\rceil\right\},
 \max\left\{1,\left\lceil\frac{w_i^{\rm mm}}g\right\rceil\right\},
 \max\left\{1,\left\lceil\frac{h_i^{\rm mm}}g\right\rceil\right\}\right).
 \label{eq:box-grid}
\end{equation}
This is conservative: the usable pallet is not enlarged and the boxes are not
shrunk.  A feasible integer-grid packing therefore remains within the physical
pallet boundary, subject to the small numerical tolerances used while parsing.

\subsection{Sets and indices}

Let $n$ be the number of records in the instance.  Model construction requires
$1\le n\le n^{\max}$, where $n^{\max}$ is the configuration value
\texttt{max\_items}.  This is a preprocessing guard, not a MILP constraint.
Define
\begin{align}
 \Items&:=\{0,\ldots,n-1\}, && i,j\in\Items,\label{eq:items}\\
 \Pallets&:=\{0,\ldots,P^{\max}-1\}, && p\in\Pallets,\label{eq:pallets}\\
 \Pairs&:=\{(i,j)\in\Items^2:i<j\},\label{eq:pairs}\\
 \OPairs&:=\{(i,j)\in\Items^2:i\ne j\}.\label{eq:ordered-pairs}
\end{align}

The candidate-pallet count $P^{\max}$ is determined before model construction:
an explicit command-line \texttt{--max-pallets} value takes precedence.  If it
is absent, the code takes the maximum of the configured value and an available
instance recommendation.  That recommendation is read from
\texttt{meta.bounds.ub\_pallets\_heuristic}, or otherwise from the last entry
of \texttt{meta.bounds.certified\_optimum\_in}.  Candidate pallets are
physically identical; their labels have no physical meaning.

For each $i\in\Items$, preprocessing first generates distinct orientation
triples.  The configuration value \texttt{rotation\_mode} has the following
meaning:
\begin{description}[leftmargin=2.8cm,style=nextline]
 \item[\texttt{none}] only $(\ell_i,w_i,h_i)$;
 \item[\texttt{yaw}] $(\ell_i,w_i,h_i)$ and $(w_i,\ell_i,h_i)$;
 \item[\texttt{metadata}] the same yaw-only behavior in the current code;
 \item[\texttt{six}] all distinct permutations of the three dimensions.
\end{description}
If \texttt{upright\_only} is true, only the two yaw orientations are allowed
even in \texttt{six} mode.  Duplicate triples caused by equal side lengths are
removed.  The reduced model then removes every orientation that does not fit
inside $(L,W,H)$.  The resulting set and its fixed dimensions are
\begin{equation}
 \Orients_i:=\{0,\ldots,m_i-1\},\qquad
 (d^x_{io},d^y_{io},d^z_{io})\in\Z_{>0}^3,quad o\in\Orients_i.
 \label{eq:orientations}
\end{equation}
Every retained triple satisfies $d^x_{io}\le L$, $d^y_{io}\le W$, and
$d^z_{io}\le H$.  An item with no retained orientation is rejected before the
MILP is built.  The current exception path contains a minor implementation bug:
it refers to \texttt{item\_id}, whereas the data class field is \texttt{id}.

If \texttt{support.mode = full}, then $\widetilde\alpha=1$.  In
\texttt{fraction} mode, the code converts the configured floating-point value
$\alpha$ to a decimal string and applies a denominator-limited rational
approximation:
\begin{equation}
 \widetilde\alpha:=
 \operatorname{limitDenominator}_{1000}
 \bigl(\operatorname{Fraction}(\operatorname{str}(\alpha))\bigr)
 =\frac rs.
 \label{eq:rational-alpha}
\end{equation}
Thus the MILP enforces $\widetilde\alpha$, which need not equal an arbitrary
configured $\alpha$.  The supplied value $0.75=3/4$ is represented exactly.
The post-solve geometry audit instead checks the original floating-point value.

\subsection{Parsed attributes not used as physical constraints}

The parser reads or defaults the following additional item fields: ID, SKU,
original millimetre dimensions, weight, \texttt{volume\_dm3}, family, food,
chemical, fragile, upright-only, and retrieval priority.  ID and SKU default
from the record index; weight defaults to 1 kg; family and the food/chemical
flags may be inferred from \texttt{group}; the Boolean handling flags default
to false; priority falls back from \texttt{retrieval\_priority} to
\texttt{priority} and then to 1.

The optimization volume is $v_i=\ell_iw_ih_i$, not the parsed
\texttt{volume\_dm3}.  Weight, food/chemical status, fragility, family, and
retrieval priority do not impose payload, compatibility, accessibility, or
handling constraints in this solver.  Some of them are used only in the
identical-item key in Section~\ref{sec:symmetry}; the fields are otherwise
retained for output and future extensions.

\begin{equation}
 B_i:=\sum_{o\in\Orients_i}d^x_{io}d^y_{io}r_{io}.
 \label{eq:base-expression}
\end{equation}

integer.  The reduced class also uses integer as its fallback if the option is
omitted.

\section{Objective}

The only optimization objective inserted into Gurobi is
\begin{equation}
 \min\quad\sum_{p\in\Pallets}u_p.
 \label{eq:objective}
\end{equation}
It minimizes the number of used pallets.  No weight, center-of-mass,
accessibility, compatibility, or height objective is present.

\section{Assignment, orientation, and containment}

Each box is assigned to exactly one pallet and receives exactly one retained
orientation:
\begin{align}
 \sum_{p\in\Pallets}a_{ip}&=1 &&\forall i\in\Items,\label{eq:assign-once}\\
 \sum_{o\in\Orients_i}r_{io}&=1 &&\forall i\in\Items.\label{eq:orient-once}
\end{align}
Assignment activates a pallet, and a pallet may not be marked used without a
box:
\begin{align}
 a_{ip}&\le u_p &&\forall i\in\Items,p\in\Pallets,\label{eq:activate}\\
 u_p&\le\sum_{i\in\Items}a_{ip} &&\forall p\in\Pallets.\label{eq:used-box}
\end{align}

Define the oriented dimensions as linear expressions
\begin{equation}
 D_i^a:=\sum_{o\in\Orients_i}d^a_{io}r_{io}
 \qquad a\in\{x,y,z\}.
 \label{eq:oriented-dimensions}
\end{equation}
The endpoints are
\begin{align}
 \bar x_i&=x_i+D_i^x,& \bar x_i&\le L,\label{eq:x-bound}\\
 \bar y_i&=y_i+D_i^y,& \bar y_i&\le W,\label{eq:y-bound}\\
 \bar z_i&=z_i+D_i^z,& \bar z_i&\le H
 &&\forall i\in\Items.\label{eq:z-bound}
\end{align}
Together with nonnegative coordinates, these constraints keep every oriented
box inside its assigned pallet's local coordinate system.

The following volume inequality is a valid strengthening for each pallet:
\begin{equation}
 \sum_{i\in\Items}v_i a_{ip}\le Vu_p
 \qquad\forall p\in\Pallets.
 \label{eq:volume-capacity}
\end{equation}
If $K^{\rm vol}>P^{\max}$, the solver rejects the instance before completing
the model.  Otherwise, the reduced implementation fixes
\begin{equation}
 u_p=1\qquad p=0,\ldots,K^{\rm vol}-1.
 \label{eq:fixed-volume-prefix}
\end{equation}
It does not insert a separate, redundant aggregate row
$\sum_pu_p\ge K^{\rm vol}$.

\section{Pairwise non-overlap}

The direction variables describe exact interval separation.  For every
ordered pair $(i,j)\in\OPairs$,
\begin{align}
 \bar x_i&\le x_j+L(1-\lambda^x_{ij}),&
 x_j&\le\bar x_i-1+L\lambda^x_{ij},\label{eq:x-direction}\\
 \bar y_i&\le y_j+W(1-\lambda^y_{ij}),&
 y_j&\le\bar y_i-1+W\lambda^y_{ij},\label{eq:y-direction}\\
 \bar z_i&\le z_j+H(1-\lambda^z_{ij}),&
 z_j&\le\bar z_i-1+H\lambda^z_{ij}.
 \label{eq:z-direction}
\end{align}
Because the coordinates are integer, these paired inequalities imply, for
example,
\begin{equation}
 \lambda^x_{ij}=1\quad\Longleftrightarrow\quad \bar x_i\le x_j.
\end{equation}
If the relation is false, $x_j\le\bar x_i-1$, so the two $x$ intervals overlap
strictly or box $j$ lies completely to the left.  Touching faces count as
separation, as required for non-overlap.

For each unordered pair, at least one of the six separating directions must
hold whenever the boxes share any candidate pallet:
\begin{align}
 &\lambda^x_{ij}+\lambda^x_{ji}
 +\lambda^y_{ij}+\lambda^y_{ji}
 +\lambda^z_{ij}+\lambda^z_{ji}\nonumber\\
 &\hspace{2cm}\ge a_{ip}+a_{jp}-1
 \qquad\forall(i,j)\in\Pairs,\ p\in\Pallets.
 \label{eq:nonoverlap}
\end{align}
If $i$ and $j$ are assigned to different pallets, every right-hand side is at
most zero and their local coordinates need not be separated.  If they share
pallet $p$, the right-hand side is one, which prevents volumetric overlap.

\section{Support constraints}
\label{sec:support}

The configuration selects one of four modes: \texttt{off}, \texttt{direct},
\texttt{fraction}, or \texttt{full}.  In \texttt{off} mode, no variables or
constraints from this section are created.

\subsection{Floor and direct-contact logic}

For every box $j$, the floor indicator is exact:
\begin{equation}
 z_j\le H(1-f_j),\qquad z_j\ge1-f_j.
 \label{eq:floor}
\end{equation}
Thus $f_j=1$ iff $z_j=0$.

For every ordered pair $(i,j)\in\OPairs$, contact may be selected only when the
two boxes have the same pallet assignment.  The code imposes, for every pallet,
\begin{equation}
 c_{ij}\le1-a_{ip}+a_{jp},\qquad
 c_{ij}\le1+a_{ip}-a_{jp}
 \qquad\forall p\in\Pallets.
 \label{eq:same-pallet-contact}
\end{equation}
Because each assignment vector contains exactly one 1, these inequalities
force $c_{ij}=0$ when the boxes are on different pallets.  Exact vertical
contact is activated by
\begin{equation}
 z_j-\bar z_i\le H(1-c_{ij}),\qquad
 \bar z_i-z_j\le H(1-c_{ij}).
 \label{eq:vertical-contact}
\end{equation}
Hence $c_{ij}=1$ implies $\bar z_i=z_j$: box $i$ touches the bottom of box $j$.

\subsection{Direct support mode}

In direct mode, binary overlap indicators $o^x_{ij},o^y_{ij}\in\B$ are
created for $(i,j)\in\Pairs$:
\begin{align}
 o^x_{ij}&\le1-\lambda^x_{ij},&
 o^x_{ij}&\le1-\lambda^x_{ji},&
 o^x_{ij}&\ge1-\lambda^x_{ij}-\lambda^x_{ji},\label{eq:direct-overlap-x}\\
 o^y_{ij}&\le1-\lambda^y_{ij},&
 o^y_{ij}&\le1-\lambda^y_{ji},&
 o^y_{ij}&\ge1-\lambda^y_{ij}-\lambda^y_{ji}.
 \label{eq:direct-overlap-y}
\end{align}
These are exact indicators of strictly positive overlap on the two horizontal
axes.  Contact is gated by
\begin{equation}
 c_{ij}\le o^x_{\min\{i,j\},\max\{i,j\}},\qquad
 c_{ij}\le o^y_{\min\{i,j\},\max\{i,j\}}.
 \label{eq:direct-contact-overlap}
\end{equation}
Every box must then be on the floor or have at least one direct supporter with
positive footprint overlap:
\begin{equation}
 f_j+\sum_{i\in\Items\setminus\{j\}}c_{ij}\ge1
 \qquad\forall j\in\Items.
 \label{eq:direct-support}
\end{equation}
The size of the positive overlap does not matter in this mode.

\subsection{Fractional and full support modes}

In fraction and full modes, the reduced formulation computes the exact
horizontal rectangle intersection for every $(i,j)\in\Pairs$.  Gurobi general
constraints implement
\begin{align}
 m^x_{ij}&=\min\{\bar x_i,\bar x_j\},&
 M^x_{ij}&=\max\{x_i,x_j\},\nonumber\\
 \delta^x_{ij}&=m^x_{ij}-M^x_{ij},&
 q^x_{ij}&=\max\{0,\delta^x_{ij}\},\label{eq:x-overlap-length}\\
 m^y_{ij}&=\min\{\bar y_i,\bar y_j\},&
 M^y_{ij}&=\max\{y_i,y_j\},\nonumber\\
 \delta^y_{ij}&=m^y_{ij}-M^y_{ij},&
 q^y_{ij}&=\max\{0,\delta^y_{ij}\}.
 \label{eq:y-overlap-length}
\end{align}
Therefore, the exact footprint-intersection area is
\begin{equation}
 A_{ij}=q^x_{ij}q^y_{ij}.
 \label{eq:overlap-area}
\end{equation}

The product is linearized exactly using a binary expansion.  The code compares
the bit counts required by $\bar q^x_{ij}$ and $\bar q^y_{ij}$ and expands the
shorter representation.  Let $q^b_{ij}$ denote the selected overlap length,
$q^c_{ij}$ the other one, $\bar q^b_{ij}$ and $\bar q^c_{ij}$ their bounds, and
\begin{equation}
 K_{ij}:=\max\left\{1,
 \left\lceil\log_2(\bar q^b_{ij}+1)\right\rceil\right\}.
\end{equation}
The inserted linearization is
\begin{align}
 q^b_{ij}&=\sum_{k=0}^{K_{ij}-1}2^k\beta_{ijk},\label{eq:binary-overlap}\\
 t_{ijk}&\le q^c_{ij},\label{eq:product-one}\\
 t_{ijk}&\le\bar q^c_{ij}\beta_{ijk},\label{eq:product-two}\\
 t_{ijk}&\ge q^c_{ij}-\bar q^c_{ij}(1-\beta_{ijk}),\label{eq:product-three}\\
 A_{ij}&=\sum_{k=0}^{K_{ij}-1}2^kt_{ijk}.
 \label{eq:area-sum}
\end{align}
With $t_{ijk}\ge0$, Eqs.~\eqref{eq:product-one}--\eqref{eq:product-three}
give $t_{ijk}=\beta_{ijk}q^c_{ij}$ exactly.

Only an area belonging to an activated direct contact may count as support:
\begin{align}
 S_{ij}&\le A_{\min\{i,j\},\max\{i,j\}},\label{eq:support-gate-one}\\
 S_{ij}&\le A^{\max}c_{ij},\label{eq:support-gate-two}\\
 S_{ij}&\ge A_{\min\{i,j\},\max\{i,j\}}-A^{\max}(1-c_{ij}).
 \label{eq:support-gate-three}
\end{align}
Thus $S_{ij}=A_{\min\{i,j\},\max\{i,j\}}$ when $c_{ij}=1$ and $S_{ij}=0$
when $c_{ij}=0$.

With $\widetilde\alpha=r/s$, every box must satisfy
\begin{equation}
 s\sum_{i\in\Items\setminus\{j\}}S_{ij}
 +r\bar A_jf_j
 \ge rB_j
 \qquad\forall j\in\Items.
 \label{eq:fractional-support}
\end{equation}
For a raised box, $f_j=0$, so the selected direct-support areas must cover at
least the rationalized fraction $r/s$ of its oriented base area.  For a floor
box, $f_j=1$ and $B_j\le\bar A_j$, so the row is automatically satisfied.  In
full mode, $r/s=1$.

\section{Pallet-label and identical-item restrictions}
\label{sec:symmetry}

The model always orders candidate-pallet use as a prefix:
\begin{equation}
 u_p\ge u_{p+1}
 \qquad p=0,\ldots,P^{\max}-2.
 \label{eq:pallet-prefix}
\end{equation}
This is valid because pallet labels are interchangeable.

If \texttt{order\_pallet\_loads} is enabled, the code also imposes
\begin{equation}
 \sum_{i\in\Items}v_i a_{ip}
 \ge\sum_{i\in\Items}v_i a_{i,p+1}
 \qquad p=0,\ldots,P^{\max}-2.
 \label{eq:pallet-load-order}
\end{equation}
If \texttt{fix\_first\_item} is enabled, it imposes
\begin{equation}
 a_{0,0}=1.
 \label{eq:first-item}
\end{equation}

\paragraph{Important interaction.}
Each of Eqs.~\eqref{eq:pallet-load-order} and \eqref{eq:first-item} can select a
valid pallet labeling in isolation, but their simultaneous use is not
guaranteed to preserve a representative of every feasible packing.  For
example, suppose a $10\times1\times1$ pallet must hold boxes of lengths 6, 5,
and 5, with the length-6 box indexed first.  The only two-pallet arrangement
puts the length-6 box alone and the two length-5 boxes together.  Fixing the
first box to pallet 0 gives loads 6 and 10, whereas load ordering requires
$6\ge10$.  The supplied default configuration currently enables both options.
Consequently, with those settings the overall configured model can exclude a
feasible packing even though the reduced coordinate geometry itself is exact.
For an exact pallet-label reduction, at least one option should be disabled or
the two conditions should be replaced by one compatible canonicalization.

If \texttt{order\_identical\_items} is enabled, boxes are grouped by the exact
key
\begin{equation}
 (\mathrm{SKU},(\ell_i,w_i,h_i),\mathrm{weight},\mathrm{family},
 \mathrm{food},\mathrm{chemical},\mathrm{fragile},
 \mathrm{uprightOnly},\mathrm{priority}).
 \label{eq:identical-key}
\end{equation}
For every consecutive index pair $(i,j)$ in a group,
\begin{equation}
 \sum_{p\in\Pallets}p\,a_{ip}
 \le\sum_{p\in\Pallets}p\,a_{jp}.
 \label{eq:identical-pallet-order}
\end{equation}
Define the injective integer encoding of a grid point
\begin{equation}
 \phi(x,y,z):=x(W+1)(H+1)+y(H+1)+z.
 \label{eq:location-encoding}
\end{equation}
When both boxes are assigned to pallet $p$, their local positions are ordered:
\begin{equation}
 \phi(x_i,y_i,z_i)
 \le\phi(x_j,y_j,z_j)+M^{\rm loc}(2-a_{ip}-a_{jp})
 \quad\forall p\in\Pallets.
 \label{eq:identical-location-order}
\end{equation}
These identical-item constraints remove permutations of records that the
implementation regards as interchangeable; they do not add a physical packing
requirement.

\section{Model summary and limitations}

The reduced MILP chooses one pallet, one retained orientation, and one integer
coordinate for every physical box.  It minimizes used pallets while enforcing
pallet activation, conservative grid containment, volume capacity, pairwise
non-overlap, the configured support rule, and enabled label/order restrictions.

The formulation is discrete: it does not search arbitrary continuous
coordinates, and conservative rounding may exclude packings that require
sub-grid dimensions or positions.  It also does not enforce payload weight,
center of mass, density, food--chemical separation, fragile-box restrictions,
family compatibility, retrieval accessibility, or a height-balancing
objective.  Those attributes should not be inferred from the generated
solution merely because they are present in the input and output records.
